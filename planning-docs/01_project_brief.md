# 프로젝트 기획서 초안

## 1. 프로젝트명

AI 기반 기업 HRD 통합 플랫폼

## 2. 한 줄 소개

기업 HRD 담당자가 사업 방향과 교육 니즈를 입력하면 적합한 기업 교육 프로그램과 교육 공급자를 탐색하고, 교육 계약부터 임직원 교육 참여와 만족도 조사까지 관리할 수 있는 B2B HRD 플랫폼이다.

## 3. 이해관계자 가치와 Pain Point

### 기업 HRD 담당자

기업 HRD 담당자는 사업 전략, 조직 역량, 교육 대상, 예산, 일정에 맞춰 필요한 교육을 기획해야 한다. 하지만 현재는 교육 주제 선정, 강사/교육기관 탐색, 커리큘럼 비교, 비용 비교, 교육 운영이 수작업에 크게 의존한다.

핵심 Pain Point:

- 기업 전략을 실제 교육 주제로 바꾸는 과정이 어렵다.
- 교육 공급자를 찾고 비교하는 데 시간이 오래 걸린다.
- 계약 이후 임직원 참여 현황과 만족도를 한 곳에서 보기 어렵다.

### 교육 공급자

강사 또는 교육기관은 기업 교육 역량을 보여줄 채널이 필요하다. 기존 온라인 강의 플랫폼처럼 단일 강의만 올리는 구조보다, 전문 분야/경력/커리큘럼/기업교육 이력 중심으로 자신을 소개할 수 있어야 한다.

### 기업 임직원

임직원은 기업이 계약한 교육에 참여하고, 교육 종료 후 만족도 조사를 제출한다. MVP에서는 임직원을 주요 구매자가 아니라 교육 참여자로 본다.

## 4. AI 솔루션 기획 의도

최종 서비스는 HRD 담당자가 입력한 사업 방향 또는 전략 문서를 분석해 필요한 교육 분야와 교육 공급자를 추천하는 AX 플랫폼을 지향한다.

예시 입력:

```text
전사 생성형 AI 업무 적용 확대
Cloud Native 전환
MSA 기반 시스템 현대화
```

예시 추천:

```text
생성형 AI 업무 활용
LLM API 실습
Docker/Kubernetes
MSA Architecture
Kafka Event Architecture
```

다만 현재 과제 MVP에서는 실제 LLM 기반 문서 분석이나 복잡한 추천 모델을 구현하지 않는다. 현재 구현된 recommend-service의 규칙 기반 추천 구조를 유지하고, 필요 시 키워드 매칭 또는 카테고리 매핑 정도만 확장한다.

## 5. 도메인 매핑표

PDF 가이드의 도메인 치환 방식에 맞춰 기존 온라인 강의 플랫폼 도메인을 HRD 플랫폼 의미로 재해석한다.

| 기존 템플릿 개념 | HRD 플랫폼 의미 | 구현 방향 |
|---|---|---|
| User | HRD 담당자 / 임직원 | `users` 테이블 유지, Role 문구만 재해석 |
| Instructor | 강사 / 교육기관 | `INSTRUCTOR` Role 유지 |
| Student | 기업 HRD 담당자 또는 임직원 | `STUDENT` Role을 HRD/Employee로 화면에서 표현 |
| Course | 기업 교육 프로그램 / 공급자 제공 교육 | `courses` 테이블 유지 + 일정/운영 필드 최소 추가 |
| Course Category | 교육 분야 | 기존 enum 유지, 화면에서 HRD 용어로 표시 |
| Enrollment | 교육 계약 신청 / 교육 참여 신청 | `enrollments` 테이블 유지 |
| Payment | 기업 교육 계약 비용 처리 | 현재 자동 성공 결제 흐름 유지 |
| Recommend | 교육 추천 | 기존 recommend-service 재사용 |
| Review | 만족도 조사/결과 | 프론트 결과 조회 화면 구현, 실제 Survey API는 향후 후보 |

## 6. 핵심 사용자 흐름

```text
HRD 담당자 로그인
  -> 기업 교육 니즈 입력
  -> 키워드/카테고리 기반 교육 추천 확인
  -> 교육 프로그램/공급자 상세 확인
  -> 교육 계약 신청
  -> 현재 결제 흐름으로 계약 비용 처리
  -> 개설/신청 교육 확인
  -> 임직원 교육 참여
  -> HRD 담당자용 교육별 만족도 결과 확인
```

## 7. MVP 범위

Sprint 1 MVP:

- HRD 플랫폼 랜딩/대시보드
- 로그인/회원가입
- 교육 프로그램 목록/상세
- 교육 공급자 관점의 교육 프로그램 등록
- 교육 일정/기간/방식/대상/지역/난이도 입력
- 교육 추천 조회
- 계약/참여 신청
- 내 교육 목록 확인
- 역할별 메뉴/대시보드 분리

Sprint 2 확장:

- 현재 payment-service를 활용한 계약 비용 처리 흐름 강조
- HRD 담당자용 교육별 만족도 결과 조회
- 실제 Survey 제출 API 설계
- 프론트 화면 용어/흐름 정리

향후 개발 예정:

- LLM 기반 사업계획서 분석
- AI Skill Gap 분석
- 교육 공급자 매칭 점수 고도화
- 교육 결과 분석과 차기 교육 추천 자동화
- 실제 PG 결제 연동

## 8. 발표 흐름

발표 자료는 PDF 가이드 기준에 맞춰 다음 순서로 구성한다.

1. 이해관계자 가치와 Pain Point
2. 이를 해결하기 위한 AI/AX 솔루션
3. Sprint 1/Sprint 2 구분과 우선순위 이유
4. 기존 MSA를 HRD 도메인으로 치환한 아키텍처 구성도
5. 프론트가 호출하는 API 명세
6. 실제 동작 화면 스냅샷
